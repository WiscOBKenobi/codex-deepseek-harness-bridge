## 必要的兼容修复

新版官方 headless 默认关闭 managed credentials、authorization 和 DeepSeek account，因此旧桥接仅凭 GUI 保存的 Key 会认证失败。本次按照[官方三行恢复配置](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/bundle/headless/README.md#credentials)，在每次任务中显式启用 credentials、authorization、deepseek-account。

实际提供方仍为 deepseek-official，由 Harness 自己从原 home 读取已保存凭据。桥接继续移除继承的 DEEPSEEK_API_KEY，不通过 MCP 或配置复制 Key 明文。会话上传和遥测保持关闭。

新增无模型回归在独立 home 写入无效的合成非 API 引用，仅检查配置存在性与来源为 file；不读取个人凭据、不调用模型，同时核验文件守卫和隐私设置。
