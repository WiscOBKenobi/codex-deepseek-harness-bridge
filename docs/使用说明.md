# 使用说明

## 1. 先选入口

本项目的通常使用方式是：**你在 Codex 安排工作，Codex 拆分并调用 DeepSeek，最后由 Codex 检查实际产物。** Codex 保持你在客户端选择的模型；连接程序不会增加一个额外的 Codex/OpenAI API 调用层。

网页面板是可选的。一种用途是旁观已有任务进度，另一种是直接把工作交给 DeepSeek。后一种不经过 Codex 自动规划和验收：你要自己检查结果，或另外让 Codex 接手该任务。

不要把“后台一直可以运行”理解成“Codex 会自动一直醒来检查”。本项目保存并执行任务，但不会主动唤醒已经结束的 Codex 回合；自动跟进需要客户端提供调度。

## 2. 安装与配置本机

### 准备已有 Harness

本仓库不附带 DeepSeek Harness。先安装 [官方 Harness](https://github.com/deepseek-ai/deepseek-harness)，完成其依赖与构建，使其官方 headless 入口可以运行，然后在 Harness 设置中保存自己的 API Key。

本项目对接的上游基线为提交 [`477b4f420553e8a52c2fbccc464d7561b239c443`](https://github.com/deepseek-ai/deepseek-harness/tree/477b4f420553e8a52c2fbccc464d7561b239c443)。上游版本变化可能影响启动参数、插件和会话恢复，不能只凭仓库名称相同就认定兼容。

### 配置连接程序

需要已有 Node.js 24 或更高版本。双击 **配置本机.cmd**，选择 Harness 根目录和数据目录；脚本会查找已配置 Node、Harness 自带的本地 Node 或 PATH 中的 Node，不安装新的 Node 或 Harness。连接程序依赖缺失时，它会提示并使用已有 npm 安装锁定依赖。对应跨平台配置脚本为 [scripts/setup.mjs](../scripts/setup.mjs)，CLI 只生成配置、不安装依赖。不要输入或粘贴 Key 明文。

配置生成两份本机文件：

| 文件 | 用途 |
| --- | --- |
| `config.json` | Harness 路径、模型、输入目录、任务上限与停滞提示设置。 |
| `.codex/config.toml` | 当前项目的 `codex_ds_harness` MCP 启动配置。 |

两份文件均是本机配置，不应随源码分享。工具不会修改全局 Codex 配置。修改已有配置前保留所需路径和用户模型选择；不要用其他机器的绝对路径覆盖自己的设置。

给维护者的安装命令是 `npm ci`；Windows 双击流程安装依赖时使用 `npm ci --ignore-scripts --no-audit --no-fund`。它只安装本项目锁定依赖，不会安装、构建或升级外部 Harness。配置后运行 **检查环境.cmd**。检查只能证明相应文件与配置符合要求，不能证明 API Key 有效或账户额度充足。

## 3. 在 Codex 中提交第一项任务

在 Codex 中打开本项目目录，创建新任务并加载项目 MCP。界面如出现项目信任提示，按客户端要求处理。服务名为 `codex_ds_harness`，已有对话不保证自动加载新增配置。

可以直接说：

> 用本项目的 Harness 让 DeepSeek 读取 examples/numbers.json，计算数量、总和和平均值，写入 output/result.json，再写一份中文说明。你读取实际文件，独立核算后再验收。

Codex 负责把明确输入转换为完整文件路径，通过 `submit_task` 提交，保留返回的任务编号，再查询进度和读取成果。`examples/numbers.json` 是仓库内样例，默认输入范围即可使用。

本机已经明确授权并启用 agent 后，对于编码任务可以说：

> 把这个独立小功能交给 DeepSeek，用 agent 模式在任务目录建立示例工程、安装所需依赖并运行测试。输出可检查的代码和测试说明。你审阅结果后再决定如何纳入正式项目。

agent 能否完成某种操作，取决于当前 Harness 的工具、依赖和权限。不能因为选择 agent 就假定网页浏览、搜索、子代理或所有语言环境都已配置。

## 4. agent 与 files 怎样选择

| 场景 | 模式 | 行为 |
| --- | --- | --- |
| 编码、安装项目依赖、执行测试、多步骤工作 | `agent`，需显式启用 | 使用原生 Harness 工具，在独立任务 workspace 中工作。 |
| 整理指定文本、生成表格数据或修改小草稿 | `files`，默认 | 只提供 read/write/edit，读取 input/output，只允许写 output。 |

发布默认 `defaultMode: files`、`enableNativeAgent: false`。原生 agent 属于需显式授权和启用的能力；启用前服务只报告 files 可用，提交 agent 会被拒绝。修改 defaultMode 不能代替启用许可。决定启用原生编码能力后，保留其余字段，在本机 config.json 设置 `enableNativeAgent: true`；如希望省略 mode 时也用 agent，再设置 `defaultMode: agent`。先处理活动任务再重启服务。

两种模式均按清单复制输入，不自动处理整个原项目。agent 可以在 workspace 的其他位置建立工程、依赖和临时文件，但最终交付必须放到 `output` 才会进入 MCP 的产物清单。files 模式不能运行命令、安装依赖、访问浏览器或创建子代理。

旧版任务记录没有 mode 时按 files 解释。继续任务保留原模式、会话和运行限制，不会把旧 files 任务悄悄升级为 agent。要换模式或新增输入，建立新任务。

## 5. 输入、工作文件和交付

每项任务有自己的目录：

```text
.bridge/tasks/<任务编号>/
  task.json          状态、要求、各轮执行、监督与验收记录
  workspace/
    input/           明确输入文件的副本
    output/          提交给 Codex 或用户检查的成果
    ...              agent 可在这里建立工程与临时工作文件
```

`inputs` 只接受明确的普通文件，每次最多 30 个，不接受目录或通配符。来源必须属于 `config.json` 的 `readRoots`，默认仅本项目；需要其他目录时先明确授权，再增加相应范围。授权目录并不等于自动导入目录内容。

文件按原文件名复制，所以同一任务的输入不能重名。复制检查会拒绝链接、某些凭据文件和敏感目录，以及检测到的疑似 Key 或令牌；检测规则不能代替人工判断是否允许把资料发送给模型。

任务目录不同，不代表 agent 具备完整操作系统隔离。files 的工具守卫具有更窄的文件操作范围；agent 沿用原生 Harness 权限，Windows 仅有部分隔离，读取和网络能力不能一概描述成被完全限制。

连接层只收集 output，不自动复制回原工程。Codex 应检查文件内容、计算和必要测试后再整合。模型声称成功、测试摘要或文件名称，都不能替代查看实际交付。

## 6. 长任务与持续监督

默认 `maxRuntimeSeconds=0` 和 `maxToolCalls=0`，表示连接层没有时长或工具次数截止。模型正常完成、运行失败、用户取消或权限阻断时，任务仍会结束；这不是自动无限续问的循环。

可以为具体任务设置非零时长或次数，限制单轮工作规模。若项目配置已有非零上限，请求不能把它扩大或用 0 绕过。继续任务沿用原限制。

`get_task` 每次最多等待 25 秒，只是一次查询的等待时间。一次查询返回、MCP 调用结束或 Codex 回合结束，都不等于任务寿命结束。

监督包含两种不同信号：

| 信号 | 表示什么 | 不能据此推断什么 |
| --- | --- | --- |
| 每 15 秒监督心跳 | 监督进程仍在响应。 | 模型一定有新进展、工具必然没有卡住。 |
| 可识别进展 | 模型流、工具开始/结束或后台输出等事件发生。 | 结果已经正确或已经完成验收。 |

默认 300 秒没有新进展时显示“疑似停滞”，只提示检查，不自动结束任务。合法的长时间测试也可能触发提示；先看活动工具和最近进展，再决定等待、取消或调整工作要求。

本地等待、轮询和心跳不生成模型 token；Codex 每次读取状态并作判断仍消耗自身用量，DeepSeek 执行使用你的 DeepSeek API 额度。0 截止不是免费、无限上下文或费用承诺。

## 7. 关闭、取消、继续与验收

| 操作或事件 | 实际影响 |
| --- | --- |
| 关闭面板、关闭 Codex 或 MCP 断开 | 后台 daemon 仍持有活动任务。 |
| 取消单项任务 | 请求该任务停止，等待进程结束；已写文件保留。 |
| 停止任务服务 | 结束本项目活动任务并关闭服务。 |
| 电脑休眠 | 不能继续执行；恢复后连接或外部工具可能需要处理。 |
| 关机、服务异常退出 | 不能持续工作；重启后遗留活动任务标为 interrupted。 |
| 继续任务 | 有有效会话时，复用目录与会话执行明确补充要求。 |
| 标记验收通过 | 记录检查结论，不自动应用或发布产物。 |

取消过程中会显示 `cancelling`，应等到终态再确认已结束。异常恢复不会自动重放或无限重试；先检查已有文件，有会话记录时明确继续，没有会话记录时再提交新任务。

同一交付继续后，验收状态回到 `pending`。只有运行成功的任务才能标记 `accepted`，且应针对最新实际文件；`needs_changes` 只记录意见，不自行触发返工。

提交和继续都建议带固定 `requestId`。响应不明时先查已有任务或使用同一编号恢复，不换新编号反复提交，以免重复调用 API。

## 8. 可选网页面板

双击 **打开任务面板.cmd**，可以查看服务状态、任务列表、监督信号、产物和验收记录。面板仅提供本机访问，启动入口负责认证，无需手工拼接地址。

在面板里填写任务并提交，就是直接交给 DeepSeek。它没有自动通过 Codex 规划，也没有自动让 Codex 验收。你可以自己检查并记录验收，或回到 Codex 请它查阅已有任务并核对；不要为“让 Codex 看看”重复创建相同任务。

**检查环境.cmd** 用于检查运行条件。**停止任务服务.cmd** 会停止本项目后台服务及其任务。日常只用 Codex/MCP 时，不需要保持网页打开。

## 9. 凭据与配置

Key 始终由已有 Harness 管理。连接程序向 Harness 提供 home 路径，不要求在本项目配置、面板或 MCP 参数中复制 Key。更新 Key 应到原 Harness 设置界面完成。

默认模型是 `deepseek-official / deepseek-flash / max`，可以在本项目配置中明确更改。连接程序不会跟随原 GUI 当前选项实时改模型，也不会接管原 GUI 的对话。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `defaultMode` | `files` | 省略 mode 时使用的任务模式。 |
| `enableNativeAgent` | `false` | 是否明确启用原生 agent；默认关闭。 |
| `prepareWindowsWorkspaceAcl` | `false` | 可选的新 agent 任务空目录初始化，需明确授权；不递归修复已有目录。 |
| `maxRuntimeSeconds` | `0` | 无连接层时长截止；非零时对单轮生效。 |
| `maxToolCalls` | `0` | 无连接层工具次数截止；非零时对单轮生效。 |
| `maxStreamBytes` | `4194304` | 累计 stdout JSON 协议流上限；0 为无累计截止，仍逐条有限解析。 |
| `stallWarningSeconds` | `300` | 无可识别进展达到该时长后提示疑似停滞。 |
| `maxInputBytes` | `2000000` | 一次任务复制输入的总大小上限。 |
| `maxOutputBytes` | `5000000` | 文件交付收集的大小上限；files 模式还用于工具写入限制。 |
| `readRoots` | `["."]` | 明确输入的允许来源，相对本项目解析。 |

长期任务可显式配置 `maxStreamBytes: 0`，避免按累计协议流大小结束；单条消息 256 KiB 限制仍然保留。协议流、output 交付和 agent 工程占用是三个不同概念：agent 工程或依赖大小不属于 output 交付大小，输出收集上限也不是整个工程的磁盘配额。改变配置后，应先处理活动任务，再停止并重新启动服务。

## 10. 常见问题

**Codex 找不到工具。** 确认配置脚本已生成项目 MCP 配置，并在本项目的新任务中加载。配置文件存在不等于当前连接成功；本项目不会全局注册到所有项目。

**任务被拒绝读取或缺少审批。** files 只能操作 input/output。agent 的 headless 没有人工批准应答器，需要额外批准的权限请求会失败关闭；不要让模型绕过限制，应检查任务范围、运行环境及必要人工操作。

**Windows 命令启动提示 `SetNamedSecurityInfoW` / `Win32 5`。** 当前用户拥有目录，不代表继承得到的 Modify 权限包含上游所需的 `WRITE_OWNER`。此前原生初始化失败，还可能使已存在的 input/output 没有正确继承沙箱权限。先诊断具体原因，不关闭沙箱，也不给整个磁盘增加权限。

确需这项局部处理并已明确授权时，可启用 `prepareWindowsWorkspaceAcl: true`。它只在创建新 agent 任务时工作：先创建并校验空 workspace，只给根目录的原 owner 补充非继承 `WRITE_OWNER`，再调用 Harness 官方 ACL 接口初始化根目录，成功后才创建 input/output 和复制输入。新对象因此正常继承官方 capability 权限和 Low 完整性标签，不需要给后代额外追加 `WRITE_OWNER`，owner 保持不变。

发布默认 false，没有此问题的机器无需启用。继续任务使用已有正确目录，不重新递归初始化；非空、owner 不符或无法安全校验的目录会明确报错。初始化不修改全局 ACL、不降低原生沙箱，已经写入的目录权限也不会因关闭配置而自动撤销。

已有失败任务的旧目录不会被自动清空或修复。应先保留数据和备份，再按明确诊断方案创建新对象、按字节复制文件并核对哈希；不要直接删除旧文件或把“再次继续任务”当作权限修复。具体运行验证见验收记录。

**某个插件不能使用。** 查看原 Harness 是否已安装、启用和配置该能力。连接程序不承诺把所有上游插件自动配齐。

**心跳正常，但很久没有产物。** 心跳不是进度。查看最近进展类型、活动工具和疑似停滞提示，再决定是否继续等待或取消；不要因心跳正常直接标记成功。

**API 失败或没有额度。** 环境检查不验证账号有效性。查看原 Harness 设置和服务返回的错误，不把 Key 粘贴进任务文本。

**服务重启后已中断。** 先检查保留的产物，确认是否有会话可续，再明确继续。不会因为打开面板就自动重跑。

**想让 Codex 定期醒来监督。** 连接层提供查询与持续后台执行，不提供主动唤醒已结束 Codex 回合的能力。需要客户端自身调度功能另行安排；不要把本地心跳误当 Codex 调度。

## 11. 分发到另一台电脑

源码包包含连接程序、锁定依赖清单、示例、测试、文档和技能，不包含外部 Harness、Node、已安装依赖、个人 Key 或任务数据。接收者需准备运行条件并执行自己的本机配置步骤。

不要发布 `config.json`、生成的 `.codex/config.toml`、`.bridge`、`node_modules` 或本地运行环境。需要共享结果时，先选择允许共享的交付文件，不直接把整个任务目录作为诊断包上传。

详细参数见 [架构与接口](架构与接口.md)，实际测试范围见 [验收记录](验收记录.md)。
