## Required compatibility fix

Upstream 0.2.1 disables managed credentials, authorization, and the DeepSeek account provider in its shipped headless profile. An old bridge relying on a Key saved in the GUI would fail authentication. Following the [official restoration overlay](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/bundle/headless/README.md#credentials), the runner now explicitly enables the `credentials`, `authorization`, and `deepseek-account` rows for its task processes.

The selected API-key provider remains `deepseek-official`. Harness resolves the saved Key in its existing home; the bridge still strips inherited `DEEPSEEK_API_KEY` and does not copy Key values through config or MCP. Session upload and telemetry remain disabled.

The keyless integration fixture uses a synthetic non-API reference in an isolated home and inspects only credential presence/source. It verifies a `file` source alongside the actual file-tool guard and privacy checks, without accessing personal credentials or making a model request.
