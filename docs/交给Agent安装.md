# 交给自己的 Agent 安装

这条路径让能操作你电脑的主 Agent，按 [安装 SOP](安装SOP.md) 下载、安装、构建和配置。它不是一个已经内置所有依赖的安装器，也不要求主 Agent 把自身模型改成 DeepSeek。安装完成后，主 Agent 通过本项目 MCP 委派任务。

Agent 需要有本机文件、命令执行和网络下载能力；所在客户端若受限，仍须遵守其真实权限。普通网页聊天无法仅凭一个仓库链接就替你安装本机软件。仓库为 private 时，还需要现有合法 GitHub 访问权限或用户提供的源码包。

## 给用户：复制这一段即可开始

把下面文本发给自己的本机 Agent。先填写或替换“安装目录”；运行模式、权限选择和真实验收选择可以按自己的需求修改。若你同意下面的默认选项，复制发送后就是针对这些事项的明确授权，不需要 Agent 为同一项反复询问。

```text
请帮我在这台电脑安装 Codex × DeepSeek Harness：
https://github.com/WiscOBKenobi/codex-deepseek-harness

安装目录：选择当前用户可写的独立 AI-Tools 文件夹；如果我已经指定目录或已有兼容安装，优先复用。
运行模式：agent。我允许 DeepSeek 在本项目新建的独立任务工作区运行命令、安装项目依赖和执行测试；保持原生沙箱，不自动批准需要额外权限的操作。我理解 Windows 不提供完全的读取和网络隔离。
新任务权限：Windows 上允许仅对本项目新建空 workspace 的原所有者补非继承 WRITE_OWNER，并用官方沙箱初始化；不更改 owner、其他用户或整盘权限，不递归改已有工程。其他系统不执行此 Windows 处理。
运行限制：不设总时长、工具次数和累计协议流上限；保留单条消息、交付大小、取消和停滞提示。
真实验收：我填好 Key 后，允许一次小规模 files 验收，以及一次简单命令与测试的 agent 验收；失败先诊断，不无限重试。

请先读取仓库 README、AGENTS.md、docs/安装SOP.md 和 docs/交给Agent安装.md，再落实安装。保留我当前主 Agent 的模型。
自动完成：核对已有工具，下载兼容版本的官方 Harness，安装锁定依赖、构建、配置本项目路径和项目 MCP、完成不调用模型的检查。只有缺失工具才安装，使用官方来源；优先项目本地或便携环境，不改变全局配置。大型系统组件或扩大权限另行说明。
需要 Key 时，打开官方 Harness 的 API Key 输入页面，让我自己填写；不要让我把 Key 发到对话，不读取、回显、复制或截图 Key，不把它写进本项目配置或 GitHub。
尽量先完成全部不依赖 Key 的准备工作。配置好后，指导我按客户端提示加载 MCP，再做我已允许的真实验收。
最后交付：安装路径、实际版本、密钥填写入口、MCP连接状态、真实验收结果、未完成事项，以及以后如何在对话里调用和取消任务。不要把“文件下载成功”当作“安装验收完成”。
```

如果只想处理文件，将运行模式改为 files，并把“新任务权限”改为不启用，同时删除 agent 真实验收。若暂不允许任何 API 消耗，把真实验收改为“只做无模型检查，保留待验收状态”。

用户仍需要亲自处理账户登录、填写 Key，以及客户端要求的项目信任或系统许可。其余在授权范围内可由 Agent 连续完成。Key 的准确页面路径见 [安装 SOP 第 3 步](安装SOP.md#3-打开-harness并亲自填写-api-key)。

## 给安装 Agent：执行顺序

### A. 盘点并取得源码

读取用户选择与目标目录，核实主机操作系统、Node、npm、Git、pnpm 的实际路径和版本。先检查已有安装与 PATH，不因单个命令未发现就重装。Windows 首选已有 Node 24+；缺失时从官方来源安装必要组件，尽量把便携工具放在与两个项目并列的独立 tools 目录，避免混入本项目源码。系统级安装和大型组件服从用户授权及宿主权限，不自行安装 Docker、WSL 或完整编译套件。

取得本项目代码；私有仓库复用已有 GitHub 登录，不能访问时要求用户授予访问或提供源码包，不索取令牌明文，也不改变仓库可见性。保留现有修改，不覆盖非空目录。

官方 Harness 新安装固定到 `dsh-v0.2.0-rc.2` 的提交 `639ed015397290b3745d163aafe02ffee4aa3f84`，使用其 package.json 声明的 pnpm 11.7.0。只对本次新克隆目录 checkout 固定提交；已有 Harness 先核对版本、构建和数据目录，不能为符合示例而重置用户工程。安装命令见 [手动 SOP](安装SOP.md#2-下载并构建官方-harness)，每条原生命令检查退出码，失败后不继续串行执行。Windows 的 npm/pnpm 优先用 .cmd 入口，避免因同名 .ps1 受限而修改全局执行策略。

复用已有 Harness 时，先按 [已有安装的升级步骤](安装SOP.md#更新已有-harness) 查看官方发布变化和升级指南，核对与本项目的入口、提供方、插件及数据迁移兼容性。保留用户配置、凭据数据目录和本机启动器；更新共用安装前确认没有活动或排队任务并正常停服。只在本机改动可保留且分支可快进时更新，否则先处理具体情况或另建安装目录验证，不能用 git reset、git clean 清理用户工程。重新安装锁定依赖、构建并完成本机验收后，才报告升级完成；不能把文档中的固定提交当作已在用户机器验收的证据。

### B. 安装构建，并准备一致的数据目录

完成官方 Harness 的锁定依赖安装与构建；本项目使用 `npm ci --ignore-scripts --no-audit --no-fund`。安装依赖与模型请求是不同动作，不要为测试安装过程额外发起模型任务。

新安装使用明确的数据目录，例如 Harness 下的 `.local/dsh-home`。既有安装保留实际目录，默认 home 不应凭目录名称推测。官方 Web 设置页面与桥接 `harnessHome` 必须指向同一个 home，否则用户虽然保存过 Key，任务仍会显示未配置。

有本机命令能力的 Agent 无需弹出连接程序的目录选择器，可从本项目根目录调用已有配置脚本：

```powershell
node scripts/setup.mjs --harness-root '<Harness绝对路径>' --harness-home '<实际数据目录绝对路径>' --node-path '<node.exe绝对路径>'
```

尖括号内容是待替换路径，不能原样执行。脚本需要这些路径已存在；它生成本机 config.json 和项目 .codex/config.toml，保留已有模型与其他 MCP 设置，不安装外部 Harness，也不读取凭据。遇到不支持的已有 TOML 格式，应保留原文并处理明确问题，不能直接覆盖整份客户端配置。

按照用户已经明确选定的模式修改本机配置，保留其余字段。agent 对应 `enableNativeAgent: true`、`defaultMode: agent`；选择长期运行时将三个累计上限设为 0。Windows 局部初始化只在用户已授权的本项目新任务范围内设 `prepareWindowsWorkspaceAcl: true`；授权已在任务中提供时不要重复索取。不能把当前项目配置复制成他人机器的固定绝对路径，也不能把用户对本机的授权扩展为其他人的授权。

只配置当前项目 MCP。若主 Agent 不是 Codex，使用其本地 stdio MCP 配置格式，command 指向实际 Node，args 指向本项目 src/mcp-server.mjs，cwd 指向本项目根目录；用户没有要求时不改全局模型、不公开本机端口、不架设远程隧道。新增 MCP 往往需要重新加载客户端或新建对话，不承诺当前回合自动获得新工具。

### C. 用户填写 Key，Agent 做独立准备

按手动 SOP 指定同一个 DSH_HOME，启动官方 `pnpm dsh web`，把用户带到首次 API Key 表单，或“设置 → 模型 → DeepSeek 官方提供方 → 编辑”。用户亲自输入保存；不要读取 .credentials.yaml 的内容，也不要要求把 Key 发到对话。可以检查凭据文件存在与否，但不能把存在性当作有效性验证。

等待填写期间，完成构建、配置、语法检查与本机 MCP 连通性检查，不让用户等待一套尚未准备好的安装。无模型阶段运行 `npm run check`，按需执行 `npm test`；逐项报告通过、跳过与失败。仅缺少用户尚未填写的凭据时，准确标记该检查待完成，保留其余准备结果。

通过官方 MCP 客户端验证 initialize、tools/list 的七个工具及 list_tasks。也可用本项目 tests/mcp.test.mjs 验证协议实现，但测试客户端通过不代表用户正在使用的客户端已经加载：要分开记录“程序可连”和“当前主 Agent 已发现工具”。这些检查不提交模型任务。

### D. 验收并交付

仅在用户已允许 API 调用且填写 Key 后，执行一次 [手动 SOP 的小文件任务](安装SOP.md#7-做一次小任务验收再开始日常使用)。保留 requestId；提交结果不明时先查原任务，不换编号重复提交。

用户启用了 agent 且允许原生命令验收时，再提交一个有明确输入、交付与测试标准的小任务，在新任务目录生成简单函数和少量测试，实际运行测试并将报告放 output。若启用了 Windows 新目录初始化，要验证新建工作区的真实流程，不能只依赖配置字段或模拟测试。独立检查产物和测试报告，再记录 review_task；模型总结或 succeeded 状态不是独立验收。

不要把用户机上的 API 任务结果、凭据、本机配置、依赖或数据目录提交 Git。不要默认执行两个真实测试脚本的全套回归来消耗额度；选择用户授权且足以验收的小任务。若操作被实际权限、网络、依赖或账户状态阻止，交付准确的已完成部分和具体阻碍，不关闭沙箱或无限重试。

最终返回以下信息，不带 Key：

| 项目 | 交付内容 |
| --- | --- |
| 位置与版本 | 两个源码目录、Harness 提交、Node/pnpm 版本、实际数据目录。 |
| 凭据 | 用户是否已在指定页面保存；仅报告状态，不读取或输出值。 |
| 模式与限制 | files/agent、局部目录初始化是否启用、时长与工具上限。 |
| 接入 | 项目 MCP 配置路径；当前客户端是否真正加载七个工具。 |
| 验收 | 无模型检查结果；付费任务是否实际执行、文件与测试是否独立核对。 |
| 日常入口 | 在主 Agent 说“交给 DeepSeek”或“取消这项任务”；不要求先打开面板。 |
| 维护 | 本项目后台可按需自动启动；手动入口只用于配置、检查和维护。 |
| 剩余事项 | 未验证的平台、未安装的可选插件或仍需用户处理的实际问题。 |

准确的启停影响见 [使用说明](使用说明.md#7-关闭取消继续与验收)。本 SOP 不把创建插件市场、公开发布服务、同步其他用户资料或安装所有可选 Harness 插件作为默认安装步骤。
